# Scenarios — the hand-written cases, one JSON file per node

A file is `scenarios/<catalog typeName>.json` holding an array. Each entry is one scenario, played from a
fresh mount on the reference (the spec interpreter) and on the target under test; the two traces are
compared line by line. The runner reads these files (`src/runner/scenario.ts`); a target's author reads
this page (NSP-006 asked for it).

```json
{
  "name": "Reset when already at Start Value reports unchanged",
  "params": { "startValue": 3 },
  "steps": ["settle", { "signal": "reset" }, "settle"],
  "because": "counter.ts :107-117 — the FH-022 guard"
}
```

| field | meaning |
|---|---|
| `name` | unique in the file; what the report prints |
| `params` | the node's parameters at mount, applied as ordinary writes in this key order (adapter.ts `mount`) |
| `steps` | in order: `{ "set": "<port>", "value": … }` (omit `value` to write `undefined`), `{ "signal": "<port>" }`, `{ "advance": <ms> }` (NSP-007: the world's clock moves — what the world already delivered lands, the clock moves and fires what is due, what that delivered lands), `{ "act": "<act>", "value": … }` (NSP-016: a PERSON does `act` to a visual node on the page — one of the acts its spec declares: `click`, `press`, `release`, `hover`, `leave`, `touch`, `lift`, `focus`, `blur`, `type` (a text, typed one key at a time), `key` (`Enter`), …, (NSP-016 s56) `push` / `replace` / `back` — another node's request to a Component Stack, answered with `answer` events (trace.ts), (s57) `navigate` — a Navigate's request to a Page Router (answered with `answer` events: `navigate`, and `page`, the parameters handed to the page's Page Inputs) — and `traverse` — the person's Back or Forward, the location moving to the URL the act carries (`popstate`; world.ts LOCATION), with the value the act carries or none; on the runtime the browser's events on the element a person sees, into the node's real component; the page is painted before the act), or `"settle"` |
| `world` | NSP-007, for a node whose spec declares `needs`: the world's script — `{ "seed": <n>, "network": [ { "match": { "method", "url" }, "answer": …, "after": <ms> } ] }`. `answer` is `{ "status", "statusText", "headers", "body" }` (a string body travels as text, anything else as its JSON text), `{ "error": "<message>" }` (never reaches a server), or `{ "never": true }`. The first rule whose `match` fits answers (absent `match` fits all; a `url` ending in `*` is a prefix). A request no rule answers FAILS the play (AC5). `"registry"` (NSP-012) seeds the shared records and arrays; `"timeZone"` (NSP-013) is the IANA zone the play runs in (absent: UTC); `"viewport"` (NSP-013 s13) is `{ "width", "height", "resizes": [ { "at": <ms>, "width", "height" } ] }` — a browser window whose size changes only at `at` on the world's clock (absent: no window at all, a server render); `"activation"` (NSP-015 s16) is `true` or `false` — whether the press came from a person, `navigator.userActivation.isActive` for the whole play (absent: the browser has no `userActivation`; read only with a window); `"location"` (NSP-015 s17) is the href the play's location starts at (absent: `https://app.example/`; read only with a window — a Page Router's scenarios carry a `viewport`, since a router reads the URL); `"projectSettings"` (NSP-015 s17) is the project's settings as a node reads them, e.g. `{ "navigationPathType": "path" }` (absent: `{}`, a project that set nothing); `"stack"` (NSP-015 s18) is the Component Stacks a navigation node hands its requests to — `{ "names": ["Main"], "answers": [ { "match": { "op", "target" }, "answer": "done" | "unchanged" | { "failure": { "code", "message" } } } ], "back": <answer> | [<answer>, …] }`: `names` the stacks registered (absent: none — every push is queued and never answered), `answers` first match wins (`done` when none fits), `back` what the n-th pop is told, the last repeating (absent: no Pop Component Stack sits in a pushed page); `"router"` (NSP-015 s19) is the Routers a Navigate hands its requests to, and the Router whose page a Page Inputs sits in — `{ "names": ["Main"], "answers": [ { "match": { "target", "noTarget": true, "openInNewTab" }, "answer": … } ], "page": [ { "params": { … } }, { "at": <ms>, "params": { … } } ] }`: `names` the routers registered (absent: none — every navigate is queued), `answers` as `stack`'s (`noTarget: true` fits a Target never set), told 1 ms after the call; `page` what the Router hands its page's Page Inputs — no `at` at the mount, `at` on the clock (absent: the node sits in no Router's page); `"popup"` (NSP-015 s20) is what lies outside the runtime's popup stack — `{ "components": ["Popup"], "host": false, "events": [ { "at": <ms>, "close": { "action": "closeAction-Save", "results": { … } }, "popup": <n> }, { "at": <ms>, "escape": true } ], "inside": ["Inner", "Popup"] }`: `components` what a Show Popup's Target can build (absent: none), `host: false` an app with no popup host (absent: a host), `events` what the person does on the clock — a close through the `popup`-th opened popup's Close Popup (absent: the last opened) or Escape — and `inside` the popups a Close Popup sits in, nearest first (absent: none); `"backend"` (NSP-014 s21) is the project's backends as the record nodes ask them, at the backend contract's operation (R9 — never the wire) — `{ "backends": ["main", "other"], "answers": [ { "match": { "op", "collection", "backend" }, "answer": { "ok": <what success is handed> } | { "error": "<message>" | null } | { "never": true }, "after": <ms> } ] }`: `backends` the ids the project has, the first the active one (absent: `["main"]`), `answers` first match wins — a call no rule answers FAILS the play, as a request does; (NSP-014 s33) a realtime subscription (`"match": { "op": "subscribe" }`) is answered by `{ "stream": [ { "at": <ms>, "status": "subscribed" } , { "at": <ms>, "change": { "type": "create", "ids": […], "records": […], "recordsComplete": true } }, { "at": <ms>, "error": { "message", "code", "kind" } } ] }` — what it tells, each `at` ms after the subscribe (never before 1), by the handle's rules in `src/world.ts` REALTIME — or `{ "never": true }`; `"cloudServices"` (NSP-014 s32) is the project's cloud services as Cloud Function reads them — `{ "appId", "endpoint", "deployVersion", "sessionToken" }`: the first three the project's `cloudservices` metadata as handed, `sessionToken` the session the browser holds for that app id (absent: nobody signed in there); absent altogether, the project has no cloud services. A node's `XMLHttpRequest` and its `fetch` reach the same `network` rules. (NSP-014 s34) A response may stream its body: `"chunks": [ { "at": <ms>, "text": "data: hi\n\n" }, { "at": <ms>, "end": true } ]` instead of `"body"` — each piece `at` ms after the head lands, ending with `end`, or `{ "error": "<message>" }` (failed while read), or neither (it never finishes); `src/world.ts` NETWORK, A STREAMED BODY. `"sockets"` (NSP-014 s34) is the WebSocket servers — `{ "answers": [ { "match": { "url": "ws://srv/*" }, "times": <n>, "answer": { "events": [ { "at": <ms>, "open": true }, { "at": <ms>, "message": "<text>" }, { "at": <ms>, "binary": [<byte>, …] }, { "at": <ms>, "error": true }, { "at": <ms>, "close": { "code", "reason", "wasClean" } } ], "replies": [ { "to": "ping", "with": "pong", "after": <ms> } ] } | { "never": true } | { "throws": "<message>" } } ] }`: first fitting rule answers a `new WebSocket` (a construction no rule answers FAILS the play), each event `at` ms after it; `src/world.ts` SOCKET. Absent: seed 1, no answers. The rules of the world — the clock, the random stream, what goes on the wire — are the header of `src/world.ts` |
| `wired` | P107-C155: the input ports a wire reaches for the whole play, e.g. `["run"]`. Each is connected AT MOUNT, before the params, to a source that never sends — so a setter that asks whether its port is wired (the runtime's `isInputConnected`; the spec's `world.wired(port)`) reads true, and nothing ever arrives on the wire; the steps still write the port as they always did. Absent: nothing is wired (every scenario before this; every generated sequence). Reaches the two branches NDA-017 §2 left: a Function's Script (simplejavascript.ts :386) and an Expression's text (expression.ts :611) run on their own only while Run is not wired. A port the node does not have fails the mount |
| `expect` | optional: a trace both targets are graded against; absent, the interpreter's trace is the expectation |
| `because` | free text — why the scenario exists: the docblock line, the divergence row. Written for the spec's reviewer; the rule itself is in the spec file |
| `seed` | on a replay the shrinker wrote: the generated sequence it came from |
| `row` | the §6 row of the phase's task files this scenario is KNOWN to fail under **on the runtime**, awaiting a ruling (R3 (a): the runtime wins until ruled). The runner reports the failure as `known`, not `failed` — and reports a PASS as "does not reproduce on <target>", which is expected on any target that does not carry the runtime's defect (the interpreter, a stranger's) and is a closed row on the runtime |

Values are in **canonical form** (`src/canonical.ts`): `{ "$num": "NaN" }`, `{ "$num": "-0" }`,
`{ "$num": "Infinity" }`, `{ "$date": "<ISO>" }` for what JSON cannot say; `loadScenarios` revives them and
the target receives the JavaScript value. A port name may be the empty string (String Format's `{}`).

The scenarios are the cases a person thinks of; the generated sequences (`src/runner/generate.ts`, seeded)
are the rest. A scenario whose reference trace has no observation event is refused — an arm with no
predicate grades nothing.
