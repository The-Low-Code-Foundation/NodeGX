The short answer

It's not the old Noodl CSS. The colour system is the cleanest part of the codebase: zero hex in the launcher, zero in the panel CSS, gated in CI. The two surfaces look dated for four reasons that have nothing to do with jQuery, and every one of them is something a session bumps into and routes around rather than fixes:

  • There is no type scale. Ten distinct font sizes on one launcher tab; ten in one property panel column. 141 font-size declarations in the launcher, 0 of them tokenised. Hierarchy can't exist at ten sizes in a 328px column.
  • Nothing is shared. Three tab implementations, two button components (seven computed button styles on the Templates tab), seven border radii, and each launcher tab is laid out as its own app — no content column, no max-width, no breakpoint, at a 600px window minimum.
  • The look was never designed — it was mock-parity'd, then gated. The chrome converges on three static HTML mocks a Claude session drew in July (phase 23). ~30 stylesheet comments cite them as the source of truth, and 28 tests parse the CSS text and pin specific fills, token names and class names. Every visual change reddens a test that encodes a previous session's taste as a fact.
  • The property panel is React trapped in 45 imperative shells. Every row is its own createRoot. The whole panel is destroyed and rebuilt on every click. Four hand-written functions decorate each row's DOM element after render. The rows can't see each other, so nothing can align, group, virtualise or gate as a set — which is why the same "applies when Shadow Enabled is on" hint is printed seven times under one switch.

The part that isn't the problem

Worth killing the hypothesis properly, because it's where a session would otherwise spend its first two hours.

0hex literals in the launcher's 28 stylesheets (3, all in comments)
0hex in the property panel's 7 legacy CSS files
0.html templates, bindView, this.$() — the jQuery View base class was deleted
1token file, 576 properties, light + dark, held by a hex ratchet and a var() gate that both pass today

The token system (noodl-core-ui/src/styles/custom-properties/) is one file per concern, has a real light theme (112 overrides), and is consumed 4,247 times. scripts/hex-color-ratchet.js reports 16 / 16 ✓, scripts/css-token-check.js reports every var() in 324 stylesheets resolves. Phase 23 did that work and it stuck. So "old Noodl leftovers" is the wrong frame: what's old is the shape of the panel code and the absence of a scale, not the palette.

3 · The look was mock-parity'd, then gated

Phase 23 ("the NodeGX look", July) produced three static mocks — nodegx-launcher-mock.html, nodegx-editor-mock.html, nodegx-node-picker-mock.html — and phase 24 ("mock parity") made the app match them pixel by pixel. Those mocks were drawn by a Claude session, not by a designer, and they are now the reference: LauncherPage.tsx:3-5 reads "Mock anatomy: padding 28px 32px 20px…", and ~30 more stylesheet headers defer to the same file.

Then the tests locked it. 28 unit tests open .css/.scss files from disk and assert on the text. The border-sweep/ suite pins which token a control's fill uses and computes contrast across the package boundary; LauncherButton.module.scss:54-58 names its own test: "reddens if the hover fill is ever moved one step further to bg-4." Seven tests assert on property-panel class names (property-row, property-group-chevron, sidebar-panel-dark-input, .sidebar-panel by name in style.css).

This is the constraint that's specific to how Claude works here. Every visual pass (P23, P24, P25, P39, FIX-028) ran as tasks with acceptance criteria and gates. The gates measure what's measurable — contrast ratio, hex count, token resolution — and none of them measure hierarchy, rhythm or whether the thing looks like 2026. So each session optimised the measurable, shipped something correct (AA contrast, zero hex, all tokens) and left it ugly, and the next session inherited a red-on-change test suite that treats the ugly as load-bearing. The memory file already names this pattern: "correct ≠ usable — 4th repeat."

4 · The property panel: React in 45 shells

The jQuery layer is gone, but its lifecycle survived. PropertyEditor, Ports, TabGroup, PopoutGroup and all 38 row classes extend a 36-line event shim, own a raw div, and each mount their own React root into it. 39 files call createRoot. The path from the sidebar to a text field crosses React → imperative → React → imperative → React.

1,125DOM elements rendered for one Group node's panel
250of them carry an inline style attribute
9distinct background fills in one column
40branches of if/else mapping port type → widget class, in one 283-line method

What that architecture costs, each with a scar in the code:

  • Rows can't see each other. Gating, hints, descriptions and capability badges are applied by four functions that wrap each row's DOM element after the fact (portGate.ts, portHint.ts, portDescription.ts, portDecoration.ts, 551 lines). A gate that knows only its own row prints "Offset X applies when Shadow Enabled is on. Show Shadow Enabled" — and then does it again for Offset Y, Blur, Spread, Inset and Colour. Seven copies, visible in the screenshot below.
  • The panel is thrown away on every click. SidebarModel.createPanel returns a new arrow function per selection, so React sees a new component type and remounts everything. Three pieces of state have escaped to module scope to survive it (index.tsx:35, propertyPanelViewState.ts:36-41).
  • Re-render is gated by a JSON hash that six call sites must remember to clear (Ports.ts:143,205,410,744,756), and re-rendering steals focus from the field being typed in — so changes are patched into the live DOM in place instead (Ports.ts:363-377).
  • Layout is keyed to English strings. Groups are the node definition's group text; the basic/advanced split is a hardcoded table of 27 group names (propertyPanelTiers.ts:91-127); expansion state persists by group name across all node types. Rename a group and users lose their preference.
  • Label geometry is duplicated across packages — noodl-core-ui's PropertyPanelInput.module.scss:76 restyles itself under :global(.sidebar-property-editor) to 37%/62px/160px, and propertyeditor.css:107-114 repeats the numbers for the rows that aren't React inputs.
  • Two icon systems in one column. 22 Font Awesome glyphs in 12 property-panel files — the only reason the 32KB FA stylesheet is still linked. The disclosure chevron is a literal text ▾ because importing Icon breaks the test runner (PropertyGroups.tsx:100-102).
  • Scroll, sticky and z-index are all workarounds: a 5-attempt retry to find the scroll container (Ports.ts:486-500), z-index: 1000 set on focusin and cleared 500ms after focusout so dropdowns escape clipping (Ports.ts:762-771), and sticky filtering that depends on exactly two ancestors having overflow: visible.

The rail itself (SideNavigation) is fine: React, tokenised, 52px, 11 default icons. Its one oddity is that panel order is a float registry (order: 4.6, 4.7, 8.8, 9.5) rather than a list. The ugliness is the content of the panel, not the strip.

How to unfuck it

Ordered so each step removes a constraint the next one would otherwise hit. F1–F3 are foundations and are boring; they are also the reason every previous polish pass got absorbed. F4 and F5 are the two surfaces. Nothing here touches the palette.

  1. Declare the type scale and ratchet it

    Five sizes for chrome — 11 / 12 / 13 / 15 / 20 — as the existing --font-size-* tokens, plus a display size for page titles. Delete body { font-size: 12px }. Add scripts/font-size-ratchet.js on the exact model of the hex ratchet: count raw-px font-size literals, baseline today's number, only go down. Fix the two surfaces first (~180 declarations).

    ~1 session · unlocks everything below

  2. One radius, one shadow, one box model

    Retire radii 5/7/10 from spacing.css; controls 6, cards 12, pills full. One --shadow-card, one --shadow-float (the other 11 shadow tokens have 35 consumers between them). Add a global box-sizing: border-box and delete the 143-site inset-ring workaround. Drop 19 dead @font-face blocks and the five preloads.

    ~1 session

  3. Retune the gates so they measure the scale, not the fills

    Convert the border-sweep/ and class-name tests from "token X in file Y" to "rendered control has ≥ 3:1 against its parent" and "every font-size is on the scale". Keep contrast as a gate — it was Richard's ruling — but stop pinning which fill delivers it. Until this happens, any visual change is a fight with 28 tests.

    ~1 session · the one nobody wants to do and the one that matters

  4. One launcher page scaffold, then the Templates tab

    LauncherPage becomes a real page: 1120px column, one title style, one toolbar (search + pill chips), one card. Delete LauncherButton in favour of PrimaryButton with a size prop; delete the two ad-hoc tab arrays in favour of Tabs. Then Templates gets the homepage grid with the five shots (they are already in nodegx-web; the template registry needs a thumbnail field the launcher currently sets to ''). Projects gets the same card with the thumbnail it already captures (thumbURI).

    ~2 sessions · the mockup below is the spec

  5. Turn the property rows into one React tree

    Ports stops being a view and becomes a pure function: port list → row descriptors { name, group, widget, gate, hint, description, connected }. The 40-branch if/else becomes a registry Map<predicate, Component>. The four DOM decorators become props on a single PropertyRow. The 38 row classes are already React inside — each is a 30–100 line shell around a component that already exists. Key the panel by node id so it stops remounting. Once rows are siblings in one tree, the panel gets a shared label column, group-level gating (one line per switched-off group), stable focus and free virtualisation.

    ~3 sessions · 23k LOC directory but mechanical; the P25 side-panel work that never reached the rows

  6. Then the panel design

    Only after F5 is the panel a thing you can design. The mockup below assumes it: a two-column grid, units inside the field, the connection dot as a gutter mark, compact dimension pairs, a real chevron, twelve-and-a-half-pixel labels and nothing else.

    ~1 session
