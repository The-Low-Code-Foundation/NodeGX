# TPL-017: Digital Bricks University, the 1:1 coaching template

**Added 2026-11-12** at Richard's request: *"let's do it all commit and push to live and the demo nodegx page please"*.
Built in its own repository (`digital-bricks/digital-bricks-university`, tasks DBU-00 to DBU-12) and ported here as
two folders. **The source of truth stays that repository**: change it there, then copy again (below).

| Folder | What |
|---|---|
| `templates/digital-bricks-university/` | The template: 1:1 coaching. A coach plans each learner's live sessions, homework and check-ins; learners hand in work in any form, keep a portfolio (My creations) and message the coach; the coach runs everything from one inbox. 50 cloud functions behind `nodegx.security.json`, magic-link sign-in, three schedules (`nodegx.automations.json`), Brevo-ready mail. `docs/START-HERE.md` is the first read. |
| `templates/digital-bricks-university-demo/` | The same app with its backend played by a service worker (`demo-sw.js` runs the template's own cloud functions on a made-up world in IndexedDB). Generated by the template's `tools/build-demo.mjs`; never edit it here. |

## Where it runs

- **Demo:** https://nodegx.io/templates/digital-bricks-university/ (card on https://nodegx.io/demos/). Built with
  `nodegx-deploy <demo> <out> --base-url /templates/digital-bricks-university/ --allow-development-engine`, then the
  production engine (`noodl-viewer-react`, `webpack.deploy.prod.js`) copied over. Driven 19/19 there by the
  template's `tools/drive-demo.mjs --url …`, with no console errors.
- **Production:** training.digitalbricks.io on nexus-1, replacing the `digital-bricks-training` site, which had no
  learners. On 2026-11-12 the backend and site are installed; the name moves over once mail is configured.
  `hosting/README.md` in the template is the runbook.

## Not on the shelf

Like `digital-bricks-training`, it needs a backend of its own, so it is not on the community shelf; nodegx.io's
demos page says so. Its `hosting/` folder (Caddy block, provision, off-box backup, the privacy notice) names this
deployment: anyone else hosting it changes those first.

## Found while porting (fixed in the template, worth knowing for others)

- A page that reads on `didMount` fires before an app-level gate redirects a signed-out visitor, and the read is
  refused (403). Measured only on nodegx.io, where the round trip is long enough. The template now reads only when
  `Noodl.Users.Current` is set.
- The realtime transports refuse a relative backend URL ("Backend URL is not a valid http(s) URL"), while every
  other request accepts one. A demo whose endpoint is a folder (`demo-api`) has to hand the app an absolute one.
