   reads the deployed shape (`sourceId / sourcePort`, nested `children`, `nodescope.ts:100-146`). Under the Lid
   wrote the second. OWN-001 must carry the transform or name which one an editor writes (NEEDS.md §3).
3. **`@nodegx/node-spec` is not standalone**: `record-match.ts` and `query-records.ts` import
   `@noodl/backend-contract`'s translators by relative path (30 KB in the bundle). R2's publish must declare it.
4. **Four sibling packages compile node-spec's SOURCE under their own tsconfigs** (runtime, export, viewer-cloud,
   backend-contract); the runtime's is below ES2020, so a BigInt literal in `src/` is a red runtime suite while
   the package's own gates are green. sha2.ts is 32-bit for that reason; keep ES2019 syntax in `src/`.
5. **The registry is the lever**: of 1,133 specced-but-world nodes across the templates, 950 need `registry`
   (Variables, Objects, Arrays). One shared `World` per graph moves more than anything else (CENSUS.md).
6. **The unspecced bucket is the component interface**: 1,071 of 1,229 are Component Inputs / Outputs (NSP-015 has
   them as graph scenarios, not package specs). R1's "what the engine must run" is mostly that.
7. **A conformance ledger does not exist**: nothing machine-readable says "node X conforms on the runtime at
   commit Y". Under the Lid typed it and was stale within a day (NEEDS.md §3; for P107 / OWN-010).
8. **Bug P112-S1-SINGLETON** (`dev-docs/bugs/`): the editor's singleton warning reads `allowSingleInstanceOnly`,
   which no producer sets (the library sends `singleton`); a second Page in a component warns nothing.
9. **P107 (opennoodl-0c) is adding a PERSON face to node-spec** (spec.ts, trace.ts, adapter.ts, interpreter.ts,
