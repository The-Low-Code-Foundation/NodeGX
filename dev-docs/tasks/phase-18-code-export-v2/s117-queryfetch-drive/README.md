# The wired-Fetch drive (P18 session 117, 2026-10-16)

P18-S116-QUERYFETCH: an exported Query Records whose Fetch is wired asked once at mount and never again, and the wired
Fetch was reported as "no deterministic translation". A query with a wired filter value and a wired Fetch was refused
outright, and a Create Record whose Done sent the Fetch was refused with it. Fixed by making the Fetch a handler action
in its sender's chain, reading the filter's wired values at the pulse, and asking at mount only where a box says the
runtime does (EXP-011 §84).

`fetch-desk` (generated by `gen-fetch-desk.py` from the export suite's `search-desk`) has one page: a City box whose
Value is wired into the Variable `city`, a **Refresh** button, an **Add Zed in Berlin** button that runs a Create Record,
and a Query Records on `Contact` feeding a For Each of `ContactRow`. The Filter is `city equal to <city>`, sorted by
name; `city` is wired into `qp-city`. Fetch is sent by Refresh and by the Create Record's Done. Every Run On Value Change
box is unticked, as NDA-017's settle writes them on a wired Fetch. A real `nodegx-backend` from `src` on :8597 holds
s115's ten contacts, **started fresh for each arm**, because S3 writes a row. One headless Chrome; six steps in each arm.
`EXPECTED.md` was written before the run.

Every step agrees between the runtime and the fixed export: the same rows, and the same request, key for key
(`{"city":{"$eq":"Berlin"}}`, `order: "name"`; the runtime adds `count: false`, §82.4). The table EXPECTED.md wrote
first held in every cell. S0 and S1 are the half HEAD never had: nothing asks at load or on typing, because the boxes
are applied before the inputs they govern (`nodescope.ts`), so the class arriving and the City box's mount value `""`
both meet an unticked box. S3 is the Create Record's Done reaching the Fetch: the save, then the query, in both.

The control is HEAD's refusal: "its Filter reads "city" from a wired input and its Fetch is wired … (P18-S116-QUERYFETCH)",
the For Each's wire dropped with it, and the Create Record refused ("its done output drives no translatable action"), so
no request or POST in any step. No console errors or warnings in any arm.

The screenshots after S3 (`shot-*-added.png`) show the same five rows, and two different buttons: the runtime's Button
is black with white text by default, the exported one is the browser's grey button. Filed as **P18-S117-BUTTONLOOK**.

`readings.json` holds every reading: the box's value, the page's lines and each request's body per step.

## Running it again

From this folder: `python3 -I gen-fetch-desk.py`. Emit the fixed arm from the working tree with
`(cd ../../../../packages/nodegx-export && ../../node_modules/.bin/ts-node -P tsconfig.json --transpile-only <here>/emit.ts $PWD/src <here>/fetch-desk <here>/out-fixed)`.
The control was emitted the same way from a copy of the package holding HEAD's `src` (`packages/.nx-ctl-s117`,
`node_modules` symlinked), removed straight after. Then `./build.sh` (bundles both arms with esbuild) and
`node drive.cjs`, which starts the backend (again before each export arm), `scripts/devtools/render-from-disk.js` (the
runtime arm; its viewer bundle was built 07:19 today, newer than every runtime commit) and Chrome
(`--use-mock-keychain`, a free CDP port), and stops all three when it ends. `fetch-desk/`, `out-*/`, `seeded.txt` and
`drive.log` are generated and not committed.
