# P18-S113-IDBINDREAD drive: expected readings, written before the drive

`bind-desk` (generated by `gen-bind-desk.py` from s113's generator): s113's run 1 shape. One page with a "page id"
input and two Records on that Id with **Fetch unwired**, each showing its `title` in a Text: **Shown** ("Record
properties" unstated, so ticked) and **Frozen** (unticked). Below them s113's `Rename` component: a "new title" input,
Save wired to a Set Record Properties on the same Id, and its Error in a Text.

One real `nodegx-backend` from `src` on :8594, one `Page` seeded `title: "Home"`, reset to `Home` before each arm.
Three arms in one headless Chrome, each from a fresh page load:

- **runtime**: the fixture through `scripts/devtools/render-from-disk.js`, its backend proxied to :8594;
- **export-control**: what HEAD (`2f9b16402`) emits for this app, built with HEAD's `plan.ts`, `component.ts` and
  `emitApp.ts` put back for the one emit: the effect form reads on every Id change;
- **export-fixed**: the working tree: the Id binds the row to the client's copy of the record.

The reading is the page's visible text, line by line (`innerText`; an empty Text has no line). The runtime column is
not a guess for D0–D4: s113's run 1 read it on the same graph (`../s113-recordlive-drive/readings-run1-effect-form.json`).

| step | runtime | export-control (HEAD) | export-fixed |
|---|---|---|---|
| D0 load | `Record Desk`, `Save` | same | same |
| D1 type the seeded id | no title; **no request** | Shown `Home`, Frozen `Home`; **one GET per Record** | no title; no request |

Why D5 and D6, which run 1 did not have:

- **D5.** The runtime binds `Model.get(id + 'x')`, an empty record, and `setModel` flags only the keys the record holds:
  none. So the Text keeps what the previous record put there. The fixed export's `subscribeRecord` hands nothing for an
  id nothing holds, so the row is not touched either. Stale in both, the same way.
- **D6.** Binding flags every key the record holds whatever the box says (the box governs only
  `onModelChangedCallback`), so the unticked Frozen shows the copy at the bind. The fixed export's unticked form takes
  the copy once (`subscribeRecord(…)()`). This is the only cell that grades the unticked bind.

Requests counted for `/classes/Page`: runtime and export-fixed **2 PUTs and no GET**; export-control 2 PUTs and 6 GETs.

Not predicted: the wording of D4's error line (the runtime's store says `Failed to save.`, the export's client `Could
not reach the backend at …`, two producers recorded in EXP-011 §43.6); console lines for the control's 404s.
