One graph, three homes

The todo-list template, exactly as it ships, run three ways against the same kind of backend: the running app in Chrome, the React export in Chrome, and the Swift app on the iPhone 17 simulator. Each arm signed in, added a task, closed one with a note, and was relaunched. At every step all three showed the same tabs and rows, and sent the same writes.

Nobody edited the exported code. Both exports are printed from the one plan the running app's graph becomes. Each arm got its own fresh backend seeded with the same rows, and its wire is that backend's own request log.

Where they differ

Nothing below changes what a person can do in the steps above. Each item is either a fact about the look, or something the exports leave out and say so before anything is written.

  • The colors. The running app is dark; both exports are light. The app's dark theme lives in CSS Definitions placed beside the router, which neither export carries yet. Same rows, different paint.
  • "Also keep track of projects and money". The running app offers it under the list; neither export does. The wire that shows it is one the shared plan leaves out, and both preflights name it.
  • Reads, not writes. The running app asks for the task list once more at sign-in, and asks GET /users/me when relaunched. Both exports skip those two reads. Every write is the same.
  • The Sign in labels. The running app and the Swift app draw "Email" and "Password" above the fields; the React export does not (filed as P18-EXP022-S4-LABELDROP).
  • What todo-list leaves behind. 91 parts of the graph are left out by the plan, the same 91 in both exports and in the same words. The Swift printer leaves out 5 more: list sections the React export does not draw either. Drag to reorder, a routine's dates and one follow-up prompt are among the 91.

Graded the same way

P107 wrote 85 scenarios that pin how the graph behaves: what fires, in what order, with which values. The same runner plays them against each export. A scenario an export cannot play (it needs a clock, or a part the plan leaves out) is counted outside, and never as a pass.

The two exports conform on the same 11 scenarios. On all 14 that both play, the Swift app produced exactly the React export’s trace, event for event, including the 3 places where both differ from the running app on purpose. The stores (State History, Undo, Optimistic Update, Action Dispatcher) run in the phone app as the React export’s own JavaScript, inside JavaScriptCore.
