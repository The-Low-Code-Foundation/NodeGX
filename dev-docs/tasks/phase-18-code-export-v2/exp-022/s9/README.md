## What I predicted wrong, or did wrong

- **The component name.** With the raise built, React's four still failed, each first at `componentName`: the runtime
  arm hosts each lone node in `node-spec/<id>`, both exports host the graph in `/Components/Probe`. That is the harness's
  packaging, so the harness reads it, for that port only, and only as the raiser's own Node Id.
- **Then Swift's names.** The Swift run puts 18 probes in one package (`/Components/Probe14`); my first rename matched
  only the exact name. Swift read 11 with the four failing on that one field and nothing else. Widened to `Probe<k>`.
- **A component whose only effect is the raise** printed `useEffect` with no import (sheet-desk's Home, TS2304 ×3, found
  by `the-parsers.test.ts` §C's typecheck). Fixed: the raise earns the import.
- **My wait loop waited four hours.** `pgrep -f 'jest|…|xcodebuild'` matched other sessions' long-lived wait-loop shells,
  whose command lines name the runners, so the Swift build never started. Now a check by process name
  (`ps comm`, shells excluded), and a look within a minute that the job started. And twice I ran a short file beside a
  peer's run that had just started.
- **My C3 row guessed the Swift locals** (`csvOnly`); they are the plan's (`appError`, `appError2`), as React's are.
