# The query drive (P18 session 115, 2026-10-16)

P18-S115-QUERYFILTER: an exported Query Records sent no `where`, no `order`, no `limit` and no `skip`, so a filtered
list held the whole class. Fixed by translating the node's Filter with the runtime's own translator at export time
(EXP-011 §82).

`query-desk` (generated by `gen-query-desk.py` from the export suite's `search-desk`) has one page: a Query Records on
`Contact` feeding a For Each of `ContactRow`. Its Filter is in the builder's shape: `vip = true` AND `joined >
2020-01-01` (a Date column) AND (`city starts with "Ber"` OR `age > 40`). It sorts age descending, then name, with Use
Limit on (Limit 3, Skip 1). One real `nodegx-backend` from `src` on :8595 holds ten contacts. Three arms run in one
headless Chrome. `EXPECTED.md` was written before the run.

## The run: every cell as expected

| arm | rows on the page | the query's body |
|---|---|---|
| runtime | Cleo Paris, Eve Bergen, Gus Berlin | `where` (below), `limit: 3`, `skip: 1`, `order: "-age,name"`, `count: false` |
| export-control (HEAD `5eeb07bdc`) | **all ten**, Ada … Jo, in insertion order | `{"_method":"GET"}` and nothing else |
| export-fixed | Cleo Paris, Eve Bergen, Gus Berlin | the runtime's, key for key, without `count` |

`where`, the same in both: `{"$and":[{"vip":{"$eq":true}},{"joined":{"$gt":{"__type":"Date","iso":"2020-01-01T00:00:00.000Z"}}},{"$or":[{"city":{"$regex":"^Ber"}},{"age":{"$gt":40}}]}]}`.

The runtime and the fixed export agree on every row and its order. The backend answered the query exactly as
EXPECTED.md read it: the date envelope compared as a date, the anchored regex, the two-key order, and the skip applied
after the sort.

- `count: false` is the runtime's Total Count box, always sent. The backend reads it as "no count". The export sends
  no count (§82.4).
- Both export arms send the query **twice**. That is the harness, not the export: the scaffold's `main.tsx` wraps the
  app in `<StrictMode>`, and esbuild bundles React's development build here (no `NODE_ENV` define), which mounts every
  effect twice. A production `vite build` mounts once. The control arm shows it too.

`readings.json` has every reading, request body and console line (none). `shot-*.png` are the three pages.

## Running it again

From this folder: `python3 -I gen-query-desk.py`. Emit the fixed arm from the working tree with
`(cd ../../../../packages/nodegx-export && ../../node_modules/.bin/ts-node -P tsconfig.json --transpile-only <here>/emit.ts $PWD/src <here>/query-desk <here>/out-fixed)`.
The control arm was emitted once, the same way, from a copy of the package (`packages/.nx-mut-s115`) with HEAD's
`plan.ts`, `component.ts` and `emitApp.ts` put back for that one emit, then restored and `cmp`-checked against the
working tree. Then run `./build.sh` (bundles both arms with esbuild) and `node drive.cjs`. `drive.cjs` starts the
backend, `scripts/devtools/render-from-disk.js` (the runtime arm; its viewer bundle was built 07:19 today, newer than
every runtime commit to the query code) and Chrome (`--use-mock-keychain`, a free CDP port), and stops all three when it
ends. `query-desk/`, `out-*/`, `seeded.txt` and `drive.log` are generated and not committed.
