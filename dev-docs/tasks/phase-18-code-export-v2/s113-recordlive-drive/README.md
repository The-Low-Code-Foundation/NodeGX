# The live-record drive (P18 session 113, 2026-10-15)

P18-S111-RECORDLIVE: a page shows a record through a Record; a form in another component renames it with Set Record
Properties. In the running app the page changes at once. Before this fix the exported page kept the old title.

`record-desk` (`packages/nodegx-export/tests/fixtures/record-desk`, generated by `gen-fixture.py`) has two Records on
one Id, **Shown** ("Record properties" ticked) and **Frozen** (unticked), and the `Rename` form. One real
`nodegx-backend` from `src` on :8594, one `Page` seeded `title: "Home"`, three arms in one headless Chrome. The
expectations were written first (`EXPECTED.md`).

## Run 2, the record-detail flow (Load wired to both Records' Fetch): every cell as expected

| step | runtime | export-control (HEAD) | export-fixed |
|---|---|---|---|
| D1 id typed, Load | Home / Home | Home / Home | Home / Home |
| D2 `Welcome` saved (200) | **Welcome** / Home | **Home** / Home | **Welcome** / Home |
| D4 next PUT refused, `Gone` saved | **Welcome** / Home, `Failed to save.` | Home / Home, `Could not reach the backend at http://localhost:8594` | **Welcome** / Home, `Could not reach the backend at http://localhost:8594` |

The backend held `Welcome` after D2 and after D4 in every arm. The runtime and the fixed export agree on every title in
every step. The one difference between them is the refused request's sentence, two producers (the runtime's store and
the export's client), which EXP-011 §43.6 already recorded. `readings-run2.json` has every reading, the requests and
the console errors; `shot-run2-*.png` are the pages after D4.

## Run 1, which found P18-S113-IDBINDREAD

The first fixture had Fetch unwired (the export's "effect form", which EXP-011 §43 built to read on every Id change).
The runtime arm made **no request** when the Id arrived and showed no title. The running app's Record only binds to the
copy of the record it already holds, and reads the backend only on Fetch. That is in dbmodelnode2.ts and in the
published doc. The export arms each made a GET and showed `Home`. At D2 the runtime showed `Welcome` on Shown and
nothing on Frozen: the shared-record behaviour this row is about, seen in the runtime itself.
`readings-run1-effect-form.json` and `shot-run1-*.png`.

## Running it again

unticked, which emits what HEAD did for this app; bundles each with esbuild, the endpoint compiled in), then
`node drive.cjs`. It starts the backend, `scripts/devtools/render-from-disk.js` (the runtime arm, reaching the backend
through its `/__backend` proxy) and Chrome (`--use-mock-keychain`), and stops all three when it ends. The runtime arm
runs the built viewer bundle; check it is newer than the runtime sources the drive depends on (this run: bundle
