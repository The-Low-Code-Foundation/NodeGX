# The query-parameters drive (P18 session 116, 2026-10-16)

P18-S115-QUERYPARAMS: an exported Query Records whose Filter read a wired value was refused, so the page lost its
list. Fixed by building the `where` in the page from the runtime translator's own document for each combination of
set and unset values (EXP-011 §83).

`params-desk` (generated by `gen-params-desk.py` from the export suite's `search-desk`) has one page: a City box whose
Value is wired into the Variable `city`, and a Query Records on `Contact` feeding a For Each of `ContactRow`. The
Filter is in the QueryEditor shape every wired filter in the corpus has: `city equal to <city>` AND `vip equal to
true`, sorted by name. `city` is wired into the filter's `qp-city`. One real `nodegx-backend` from `src` on :8596 holds
s115's ten contacts. Three arms run in one headless Chrome; five steps are typed into the City box in each (CDP
`Input.insertText`, Backspace to clear, focus emulation on the same connection). `EXPECTED.md` was written before the
run.

## The run

S1 to S4: the runtime and the fixed export show the same rows from the same `where`, one query per step, key for key
(`{"$and":[{"city":{"$eq":"Berlin"}},{"vip":{"$eq":true}}]}`, `order: "name"`); the runtime adds `count: false`
(§82.4). S3 is the drop rule's other side: `""` is a value, so its condition stays and matches nobody, in both.

**S0 differs, and not because of the `where`.** The runtime's first query is the fixed export's (`vip` only: `city`
unset, its condition dropped). Then the City box mounts and publishes its Value, `""` (`TextInput.tsx`
`componentDidMount` → `setText(startValue)` → `onTextChanged`), the Variable takes it, `qp-city` changes and the
runtime asks again with `city = ""`. The exported box writes the Variable only on `onChange`, so it never asks the
second time. EXPECTED.md named this reading as the one it could not settle beforehand. Filed as
**P18-S116-FIELDMOUNT** (an exported text input's Value reaches its wires only when typed in; 792 such wires on this
machine, most into Functions and record writes), not fixed here.

The control is HEAD's refusal: "its Filter reads "city" from a wired input … (P18-S115-QUERYPARAMS)", the For Each's
wire dropped with it, no request in any step. No console errors or warnings in any arm.

`readings.json` holds every reading: the box's value, the page's lines and each request's body per step.
`shot-*-berlin.png` are the three pages after S1.

## Running it again

From this folder: `python3 -I gen-params-desk.py`. Emit the fixed arm from the working tree with
`(cd ../../../../packages/nodegx-export && ../../node_modules/.bin/ts-node -P tsconfig.json --transpile-only <here>/emit.ts $PWD/src <here>/params-desk <here>/out-fixed)`.
The control was emitted once the same way from a copy of the package (`packages/.nx-ctl-s116`, `node_modules`
symlinked) holding HEAD's `querySettings.ts`, `plan.ts`, `component.ts` and `emitApp.ts`, removed straight after.
Then `./build.sh` (bundles both arms with esbuild) and `node drive.cjs`, which starts the backend,
`scripts/devtools/render-from-disk.js` (the runtime arm; its viewer bundle was built 07:19 today, newer than every
commit to the query, translator and Variable code) and Chrome (`--use-mock-keychain`, a free CDP port), and stops all
three when it ends. `params-desk/`, `out-*/`, `seeded.txt` and `drive.log` are generated and not committed.
