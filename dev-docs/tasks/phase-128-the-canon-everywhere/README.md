# Phase 128 — The canon everywhere

**Opened:** 2026-10-27 by Richard, from the three-surfaces audit
(`dev-docs/reviews/the-three-surfaces-audit-2026-10-27.md`) and the canon it produced (`docs/CANON.md`, approved the

**The one idea.** NodeGX has three surfaces a person meets: the part in the chat, NodeGX Studio, the NodeGX editor,
over the files. Each works; none knows the others, and the agent knows least. Richard's run on 2026-10-27 showed what
that costs: a fixed list typed as strings, a States node Studio cannot draw, a chip nobody can open, an agent inventing
the product's limits, no Preview, and an "add" button that calls a dialog neither Electron nor a sandboxed panel
answers. The fix is one text, `docs/CANON.md`, quoted by every surface, with the two Studio bugs, the Help tab, the
Wiring view and Preview built around it.

**Rulings carried (Richard, 2026-10-27):** the third rung is *the NodeGX editor*, no other name; a Help tab shared by
Studio and the agent; never refuse a part Studio cannot draw, say so and offer the two ways (his sentence is in the
canon verbatim); the cheaper-model sentence stays modest; "your AI coder", Claude first, not only; git and VS Code
are always followed by the editor the AI can build for a non-coder; Swift is at React's level; **"Option sets" stays as
Studio's word** (*"Keep Option Sets, it's cool"*), the canon's rule 5 names the node it is.
