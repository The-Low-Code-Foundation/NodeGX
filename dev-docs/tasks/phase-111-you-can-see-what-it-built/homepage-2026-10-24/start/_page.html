Never built an app

Build your first app with AI

Never written code? This is for you. Follow the steps in order. We’ll tell you what to download, what to click, and what to type.

Who does what

You

You have the idea. You answer questions, and you say what you like and what you don’t.

Claude

An AI you chat with, in plain English. It asks you questions, then builds the app for you.

NodeGX

A free app for your computer. Your app is built inside it. You can see it there, and change it too.

  1. 1

    Download Claude

    Claude is the AI you’ll talk to. Download the Claude app for your computer and sign in. Building apps needs a paid plan. Pro is enough to start.

    Download Claude
    Good to know
    • The Claude app has a Chat tab and a Code tab. For building with NodeGX, always use Code.
    • If it asks you to choose a folder, make a new empty folder called My apps and choose that.
    • Already use a different AI coding tool, like Kimi Code or Cline? That works too. Step 3 shows you how.
  2. 2

    Download NodeGX

    NodeGX is free. Choose the version for your computer (Mac, Windows or Linux), install it, and open it.

    Download NodeGX
  3. 3

    Connect Claude to NodeGX

    In NodeGX, click the blue Connect Claude Code button. That lets Claude build apps in NodeGX.

    Then go back to Claude and start a new conversation in the Code tab. Claude only sees NodeGX in conversations you start after connecting.

    Using Kimi Code, Cline or another tool? Click Copy the command instead (next to the button). Paste it into your AI tool and say: “Please add this MCP server so you can use NodeGX.”
  4. 4

    Tell Claude your idea

    Copy this message into Claude, then fill in the gaps in your own words. It doesn’t need to be perfect. Claude will ask about anything that’s missing.

    Need an idea?
    Message 1 · your idea

    Claude will ask you questions before it builds anything. That’s called planning, or “scoping”. It will probably ask about things like:

    • Does anyone need to log in?
    • Who can see what?
    • What does the app need to remember?
    • What do people see the first time, before anything is added?
    • Phone, computer, or both?
    • Who adds, changes or deletes things?
    • Does it send emails, or take payments?
    • What should it not do yet?

    You don’t need the answers now. It’s fine to say “I don’t know. What would you suggest?”

    Words Claude might use, in plain English
    Front end
    The part of the app people see and click.
    Back end
    The part that works behind the scenes: it saves things and does jobs nobody sees.
    Database
    Where the app keeps things, so they’re still there tomorrow.
    Logic, workflow
    The rules. “When someone clicks Book, save it and show a thank-you message.”
    Log in, auth
    People proving who they are, usually with an email and password.
    Stack
    The set of tools an app is built with. With NodeGX, this is already decided for you.
    Hosting, cloud
    Renting a computer on the internet that runs your app, so other people can use it.
    Deploy
    Putting your app onto that computer.
    Domain
    Your app’s web address, like myrunningclub.com.
    MCP, connector
    How Claude talks to NodeGX. You set this up in step 3.

    If Claude uses any other word you don’t know, ask “What does that mean?” Every time.

  5. 5

    Ask Claude to build it

    When Claude sums up the plan and it sounds right, make sure NodeGX is open, then send this:

    Message 2 · build it
    Good to know
    • Claude asks permission before it uses NodeGX. Click Allow.
    • The first version is rarely perfect. That’s normal. Tell Claude what you see and what you wanted, like “The list shows everyone, but I only want people coming on Saturday.”
  6. 6

    Open your app in NodeGX and make it yours

    Your app lives in NodeGX. You’ll find it on the NodeGX start screen under Recent projects. Open it to see every page Claude built.

    You can change anything: the words, the colours, the pictures, where things go. Claude won’t mind. If you get stuck, go back to Claude and ask for help.

    After you change something yourself, tell Claude, so it looks again before its next change:

    When you’ve made changes
  7. 7

    Put it online (when you’re ready)

    For other people to use your app, it needs to run on a computer that’s always on the internet. This is called hosting. Here’s roughly what it costs:

    App that only shows pagesNothing saved, no log-ins. Netlify has a free plan.free
    App that saves thingsLog-ins, bookings, lists. A small rented server from Hetzner, DigitalOcean or Hostinger.~$4–7 / month
    Your own web addressA domain name, like myrunningclub.com.~$10–15 / year
    Don’t get caught out
    • A first app doesn’t need anything more expensive than this. If someone offers you a big package, you don’t need it.
    • Very cheap prices often mean paying a year or two up front. Check the monthly price, and the price when it renews.

    Claude can already help you put a NodeGX app online. Ask: “How do I put this app online?” You’ll need a free GitHub account for this, and the NodeGX guide covers the basics. Soon, NodeGX will do this step for you.

Trying ideas

Build with your AI coder, on parts you can change

Set up a folder for NodeGX before your AI coder starts. Then say what you want to make. It plans the app with you, builds it from NodeGX parts, and leaves you a project you can open and change.

  1. 1

    Install Node.js

    Node.js runs the setup commands. If you don’t have it yet, download and install it.

    Download Node.js
  2. 2

    Set up a folder for your AI coder

    In a terminal, run these three lines. When Claude Code asks whether to use the nodegx server, say yes.

    npm create nodegx my-apps
cd my-apps
claude

    In a terminal, run these three lines. The first also adds NodeGX to Cline’s list of servers.

    npm create nodegx-cline my-apps
cd my-apps
cline

    Tested with the Cline command line. We haven’t checked the VS Code extension yet.

    In a terminal, run these three lines. The folder is set up for Mistral’s Large 4 model.

    npm create nodegx-vibe my-apps
cd my-apps
vibe --legacy-harness

    In Claude Desktop, NodeGX Studio will open inside the conversation while Claude builds, with a Hold button to stop it. The install will be one double-click.

    Coming soon notify me
  3. 3

    Say what you want to make

    A landing page for your band, a habit tracker, a quiz for your class. Your AI coder asks a few questions first. Then it writes a brief and a plan into the project and builds it.

  4. 4

    See it running

    Your AI coder tells you the app’s folder name. Run this to open it in your browser. The page reloads each time the app changes.

    npx @nodegx/preview my-app --open
  5. 5

    Change it yourself

    Every part lists its settings. Open the project in the NodeGX editor and change anything by hand. Or ask your AI coder to build you an editor of your own, showing only what you want to touch.

  6. 6

    Take it with you

    See first what will come across, then write the app as React source. This needs Node.js 22 or later.

    npx @nodegx/export export --dry-run my-app

    Code export is in alpha. Explore the code and build on it, but don’t ship a production app from it yet.

    Making a game? In the games we’ve built, the 3D world is plain code and the menus beside it are NodeGX. That keeps the hard part small for your AI coder. The menus stay easy to change. A kit with what we’ve learnt from those games is next.

    Add accounts and data

    Ask Claude for sign-in and the data your app keeps. It sets up the NodeGX backend for the project, with its tables, its cloud functions and the rules for who can see which rows. The rules are a file in your project that you can read.

  4. 4

    Put it on a server you own

    1. Rent a Linux server running Ubuntu or Debian, with root login. Add a domain name if you want one.
    2. Let your computer log in to it. 
      ssh-keygen -t ed25519
ssh-copy-id root@your-server-ip
    3. Ask Claude to publish. For example: “Put this app on root@your-server-ip at app.example.com.” Claude sends the app, its backend, its rules and its functions. If the server is missing something, the message says what to install. Publishing again keeps your data.

    This is new this week. We’ve tested it on a test server so far, not yet with a hosting company.

Coming from Bubble

Bring your Bubble app into NodeGX Studio

Studio works the way a Bubble builder expects: pages, elements and workflows. It imports your app’s front end and its back end. The app then runs on your own machine. Claude Code can carry on building it with you.

Comes across

The app you built

  • Pages, elements and styles
  • Workflows and custom states
  • Data types and option sets
  • Privacy rules
  • Backend workflows, which become cloud functions
  • API Connector calls, without their keys
Needs you

What you’ll redo or check

  • Plugins, which arrive as labelled placeholders
  • HTML, video, map, slider, date, file and picture inputs, also as placeholders
  • API keys and passwords, which never come across
  • Your data rows, which are a separate step

    Get NodeGX Studio

  2. 2

    Get your app out of Bubble

    On the Growth plan or above, go to Settings, then General, then Export application. On another plan, you can save each page’s files from Chrome’s developer tools instead. The import guide shows how.

    Keep it on your computerSome of these files contain your app’s API keys.
  3. 3

    Import it

    On Studio’s welcome screen, choose Import an app. Pick your export file or your folder of page files, then an empty folder for the new project. A large app takes about a minute.

  4. 4

    Read the import report

    It sits beside the project and lists every placeholder and anything that needs a decision from you.

  5. 5

    Bring your data across

    Export your data types as CSV from Bubble’s Data tab. Moving the rows in is a separate command for now, described in the import guide. Studio’s Data tab then offers to check and load them.

  6. 6

    Keep building with Claude

    Studio has a Connect Claude Code button. Ask Claude to rebuild a plugin, wire a page or tidy a workflow, and watch it happen in Studio. When you’re ready, Studio publishes to a folder you can host anywhere, with its cloud functions.

NodeGX is in public alpha: it builds real apps, and it still has rough edges. The changelog lists what changed in every release and what is known to be broken.

0.4.3 20 October 2026

The backend NodeGX runs on your computer now makes the smaller photos an app shows on its cards and lists. Saving an app sends its cloud functions only to that app’s backend, even when another app’s backend is running.

macOS — Apple silicon NodeGX-0.4.3-mac-arm64.dmg macOS — Intel NodeGX-0.4.3-mac-x64.dmg Windows — x64 NodeGX-0.4.3-win-x64.exe Linux — AppImage NodeGX-0.4.3-linux-x86_64.AppImage

What changed in 0.4.3 0.4.3 on GitHub All releases Linux .deb Linux .rpm

Updating from 0.3? The first time 0.4.3 opens a 0.3.0 project, it saves a copy beside it called <project>.before-0.4. Keep it until you’re happy with the updated project, because it’s the only one 0.3.0 can still open.

macOS is signed and notarised — no Gatekeeper workaround needed. Windows is not code-signed yet, so SmartScreen warns on first run: More info → Run anyway. Linux builds are unsigned, as is normal for Linux desktop distribution, and have no in-app updater.
