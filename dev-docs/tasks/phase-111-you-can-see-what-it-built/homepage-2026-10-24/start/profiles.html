Trying ideas

Build with your AI coder, on parts you can change

Set up a folder for NodeGX before your AI coder starts. Then say what you want to make. It plans the app with you, builds it from NodeGX parts, and leaves you a project you can open and change.

  1. 1

    Install Node.js

    Node.js runs the setup commands. If you don’t have it yet, download and install it.

    Download Node.js
  2. 2

    Set up a folder for your AI coder

    In a terminal, run these three lines. When Claude Code asks whether to use the nodegx server, say yes.

    npm create nodegx my-apps
cd my-apps
claude

    In a terminal, run these three lines. The first also adds NodeGX to Cline’s list of servers.

    npm create nodegx-cline my-apps
cd my-apps
cline

    Tested with the Cline command line. We haven’t checked the VS Code extension yet.

    In a terminal, run these three lines. The folder is set up for Mistral’s Large 4 model.

    npm create nodegx-vibe my-apps
cd my-apps
vibe --legacy-harness

    In Claude Desktop, NodeGX Studio will open inside the conversation while Claude builds, with a Hold button to stop it. The install will be one double-click.

  3. 3

    Say what you want to make

    A landing page for your band, a habit tracker, a quiz for your class. Your AI coder asks a few questions first. Then it writes a brief and a plan into the project and builds it.

  4. 4

    See it running

    Your AI coder tells you the app’s folder name. Run this to open it in your browser. The page reloads each time the app changes.

    npx @nodegx/preview my-app --open
  5. 5

    Change it yourself

    Every part lists its settings. Open the project in the NodeGX editor and change anything by hand. Or ask your AI coder to build you an editor of your own, showing only what you want to touch.

  6. 6

    Take it with you

    See first what will come across, then write the app as React source. This needs Node.js 22 or later.

    npx @nodegx/export export --dry-run my-app

    Code export is in alpha. Explore the code and build on it, but don’t ship a production app from it yet.

    Making a game? In the games we’ve built, the 3D world is plain code and the menus beside it are NodeGX. That keeps the hard part small for your AI coder. The menus stay easy to change. A kit with what we’ve learnt from those games is next.

  2. 2

    Build it with Claude Code

    You need Node.js and Claude Code. In a terminal, run these three lines. When Claude Code asks whether to use the nodegx server, say yes.

    npm create nodegx my-apps
cd my-apps
claude

    Tell Claude who uses the app and what they need to do. Then say what it must never do. Claude asks questions first, then writes a brief and a plan into the project before it builds anything.

    Studio and the NodeGX editor both have a Connect Claude Code button, so Claude can keep building while you watch and change things.

  3. 3

    Add accounts and data

    Ask Claude for sign-in and the data your app keeps. It sets up the NodeGX backend for the project, with its tables, its cloud functions and the rules for who can see which rows. The rules are a file in your project that you can read.

    See who can reach whose data in a real app →
  4. 4

    Put it on a server you own

    1. Rent a Linux server running Ubuntu or Debian, with root login. Add a domain name if you want one.
    2. Let your computer log in to it. 
      ssh-keygen -t ed25519
ssh-copy-id root@your-server-ip
    3. Ask Claude to publish. For example: “Put this app on root@your-server-ip at app.example.com.” Claude sends the app, its backend, its rules and its functions. If the server is missing something, the message says what to install. Publishing again keeps your data.

    This is new this week. We’ve tested it on a test server so far, not yet with a hosting company.

Coming from Bubble

Bring your Bubble app into NodeGX Studio

Studio works the way a Bubble builder expects: pages, elements and workflows. It imports your app’s front end and its back end. The app then runs on your own machine. Claude Code can carry on building it with you.

Comes across

The app you built

  • Pages, elements and styles
  • Workflows and custom states
  • Data types and option sets
  • Privacy rules
  • Backend workflows, which become cloud functions
  • API Connector calls, without their keys
Needs you

What you’ll redo or check

  • Plugins, which arrive as labelled placeholders
  • HTML, video, map, slider, date, file and picture inputs, also as placeholders
  • API keys and passwords, which never come across
  • Your data rows, which are a separate step

  2. 2

    Get your app out of Bubble

    On the Growth plan or above, go to Settings, then General, then Export application. On another plan, you can save each page’s files from Chrome’s developer tools instead. The import guide shows how.

    Keep it on your computerSome of these files contain your app’s API keys.
  3. 3

    Import it

    On Studio’s welcome screen, choose Import an app. Pick your export file or your folder of page files, then an empty folder for the new project. A large app takes about a minute.

  4. 4

    Read the import report

    It sits beside the project and lists every placeholder and anything that needs a decision from you.

  5. 5

    Bring your data across

    Export your data types as CSV from Bubble’s Data tab. Moving the rows in is a separate command for now, described in the import guide. Studio’s Data tab then offers to check and load them.

  6. 6

    Keep building with Claude

    Studio has a Connect Claude Code button. Ask Claude to rebuild a plugin, wire a page or tidy a workflow, and watch it happen in Studio. When you’re ready, Studio publishes to a folder you can host anywhere, with its cloud functions.
