Only the settings your team needs

Claude builds an editor that shows your team only what they should touch. That might be prices, opening hours or the text on a page. It reads and writes the same files as the app.

Get it: set up your project with npm create nodegx (step 2). The folder includes a guide Claude follows to build your editor.

Step 2

Build it with Claude Code

  1. Set up a folder. You need Node.js and Claude Code. In a terminal, run: 
    npm create nodegx my-apps
cd my-apps
claude
    When Claude Code asks whether to use the nodegx server, say yes.
  2. Describe the app. Tell Claude who uses it and what they need to do. Then say what it must never do. Claude asks questions first, then writes a brief and a plan into the project before it builds anything.
  3. Open it in your editor. Studio and the NodeGX editor both have a Connect Claude Code button, so Claude can keep building while you watch and change things.

Step 3

Add accounts and data

Ask Claude for sign-in and the data your app keeps. It sets up the NodeGX backend for the project, with its tables, its cloud functions and the rules for who can see which rows. The rules are a file in your project that you can read. In Studio, the Data tab shows the tables, the rules and the rows.

Step 4

Put it on a server you own

  1. Rent a Linux server running Ubuntu or Debian, with root login. Add a domain name if you want one.
  2. Let your computer log in to it. 
    ssh-keygen -t ed25519
ssh-copy-id root@your-server-ip
  3. Ask Claude to publish. For example: “Put this app on root@your-server-ip at app.example.com.” Claude sends the app, its backend, its rules and its functions. If the server is missing something, the message says what to install. Publishing again keeps your data.

This is new this week. We’ve tested it on a test server so far, not yet with a hosting company. Studio’s own Publish to a server is built and comes with its next release.
