## 1. The person sentence

> **A child picks her profile, lands on the island, taps a request, arrives in the Workshop with the
> robot, the blocks and the owl on one screen, finishes, gets her hat, and is back on the island in two
> taps — on the tablet, in French, with no scrolling to find a button.**

## 3. Acceptance criteria

1. Every screen of the mockup has its page; the plan door accepts the whole template with no warning
   other than the ones already filed as defects (D56).
2. `npm run template:garden` writes the template byte-identical on two runs (the drift gate), and the
   three phase-85 floors pass.
3. Drive: make a profile, open the island, take the tulip request, Teach four steps, see four blocks,
   fold, play, win, see the hat in My robot and the trick bloom in Skills — headless on the shipped
   `nodegx-deploy.cjs` output with the production engine, EN then FR, at 1368×912 and 390×844, 0 console
   errors, 0 network errors. Every clause has a screenshot that is looked at.
4. On 390×844 the Workshop shows the world, the controls and the owl without scrolling to find Play;
   the block list scrolls in its own box.
5. Band 7–9: no timer, no count, no text on a block beyond a caption; the pad's buttons are ≥ 56 px.
6. The Predict step (band 10–12): before Play the child taps a tile; a wrong tap shows the robot's real
   end and a hint, never a score.
7. The win card is `fixed`, centred, and reachable from a scrolled block list (P95 R6).
8. A hash change is not a navigation: page switches use the router, and a reload lands on the island
   with the profile kept.
9. The language toggle is on every screen and changes every string on the screen without a reload.
10. Two profiles on one island see each other's robots (D2), and a request done by either is done.

## 4. How to build it

- Precedents: `tpl007Components.ts` for pages built from `Game/*` parts and `Logic/*` wrappers;
  TPL-011's pages for a per-profile band and a language on the bar.
- One stylesheet reached by `cssClassName` (CG-007 fills it); no colour outside the theme tokens.
- The owl row shows the hint from the table at once and swaps in Olive's voiced line when it arrives
  (CG-005); the page never waits.

## 5. Gates

`tests/cg003Template.test.ts` (plan door, determinism, drift, floors, every `Logic/*` a named utility,
every `States` `useTransitions:false`, every colour a token); `scripts/devtools/drive-cg003-pages.js`
for AC3–AC10 with a stub Olive (CG-005).

## 6. Traps

Opening a project writes three files into it — drive a COPY; `#hash` is not a reload; the on-disk
editor bundle is not the one running; a `Select` inside a `Modal` closes it; a spec not in `index.ts`
never runs; RECT ≠ VISIBLE (`el.contains(elementFromPoint)`).

### 7.1 The first drive (orchestrator, `cline-dev`): 17 PASS, then three reds, and the fixes

1. **🔴 AC7: the win card was fixed and centred across but pinned to the top** (`cy 182.4` of 912). Cause: `.bg-win`

   align-items: center; justify-content: center; height: 100vh`, all `!important`. The gate now requires each of them.

   rows`' paints, handed to the swatch repeater: `row.fill` reads the Noodl Object's own member, never the colour). Renamed
   to `paint` (the row and `Robot/Swatch`'s input). New gate row: every list a repeater or the kit is handed (8 script
   outputs and every `Static Data` row in the graph, 11+ lists) carries no name in the editor's `RESERVED_ROW_FIELD_NAMES`;
   known-firing `fill` is reserved; arm: the field put back to `fill` is named by list (`Look rows.paints: fill`) — killed.
3. **Instrument fault in the drive:** the FR pass opened on the island because the EN pass's family survived
   `localStorage.clear()` run inside the live page, then `typeInto` threw on a missing input. Now each pass clears the
   origin's storage through CDP (`Storage.clearDataForOrigin`) before loading `/`, says `fresh family …` as a clause (and
   goes to Profiles through the bar's who pill, now `.bg-who`, if a family survived), and `typeInto` reports a FAIL line.
