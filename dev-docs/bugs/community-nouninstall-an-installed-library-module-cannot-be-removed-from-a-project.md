title: "An installed library module cannot be removed from a project: there is Install, and no Remove anywhere in the editor"
status: needs-ruling
severity: medium
area: editor / node picker Library tab (`views/NodePicker/components/ModuleCard/ModuleCard.tsx`, `models/modulelibrarymodel.ts`)
found: Community report via Richard, 2026-11-28. The builder could see installed library parts in the node picker and found no way to take them out
evidence: "Read, not driven: `ModuleLibraryModel` has `installModule` and `installPrefab` and nothing that reverses either; a search of `editor/src` for uninstall / removeModule / deleteModule finds only the user-profile uninstall. A module is the folder `<project>/noodl_modules/<name>/` (copied by `utils/import-engine/apply.ts`), and `readProjectModules` (`models/projectmodel.modules.ts`) registers whatever that folder scan finds, so its node types stay in the picker for as long as the folder exists. A prefab can also bring a dependency module with it (LBR-007, `_installDependency`)."
---

**What a person sees.** After installing a module from the Library (or cloning a prefab that depends on one), its
nodes are in the node picker for good. The card in the Library says Install / Clone; there is no "Installed" state
with a Remove, and nothing in project settings lists the project's modules.

**Workaround today.** Close the project, delete `noodl_modules/<module name>/` in the project folder, open the
project again. Any node of that type left in a component then shows as an unknown node type, which is the honest
result, but nobody is told to look.

**Proposed fix (medium).** An "Installed in this project" list (the Library tab is the natural home, since that is
where Install lives) built from `listProjectModules`, each row with Remove. Remove first counts the nodes in the
project that use the module's types and says so ("3 nodes in 2 components use this module"); on confirm it deletes
the module folder and reruns `readProjectModules` so the picker drops the types without a reopen. A module another
installed module depends on should say which one before it goes.

For prefabs the components themselves are the removal, which is COMMUNITY-FOLDERDELETE: once a component with
children can be deleted, a cloned prefab can be.

**2026-11-28, Richard:** the module half stays a guide line for now, not an editor feature. The Library page
(`docs-site/docs/library/index.md`, generated by `scripts/generate-library-docs.js`) now has a "Removing something
you installed" section: delete `noodl_modules/<module name>/` with the project closed, then reopen. The Remove
button above is the fix if this comes back.
