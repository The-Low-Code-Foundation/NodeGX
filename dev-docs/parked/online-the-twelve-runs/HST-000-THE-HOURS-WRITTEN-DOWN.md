# HST-000 — The hours, written down

**Opened 2026-10-07.** **Depends on nothing.** **Status: 📋 not started.** Kind: research.

## 1. The person sentence

> **Someone who built a site with Claude alone tells us which evenings they lost to domain names, DNS, hosting,
> GitHub and API keys. Each evening becomes a row, and each row names the thing that removes it or says plainly that
> it stays a sign-up a person does by hand.**

## 2. Why

The phase exists because Richard's ex-client said the hours of learning were the cost, not the building (README §0.1).
Nobody has that list. Without it, the phase builds plumbing it finds interesting and calls it done. With it, the
acceptance criteria are his rows.

## 3. What to do

1. Ask the client for the list, in his own words: what he was trying to do, what he had to learn, roughly how long,
   what he searched for, what finally worked. One row per evening. Richard asks; the agent does not contact anyone.
2. Add Richard's own rows from TrybeUP, Linguaid and the nodegx.io deploy (`nodegx deploy` exits 11 when it refuses;
   P91 HLS-015): the hours a developer loses are different and also count.
3. For each row, write one of: the HST task that removes it; "stays human: a sign-up with a card or KYC"; or "not
   plumbing: a design or content decision". Count the three kinds.
4. Rewrite README §7 from the rows. A row with no task is a gap in the board, not a footnote.

## 4. Acceptance criteria

1. The list exists in this folder as `THE-HOURS.md`, with the client's rows marked as his and quoted, not paraphrased.
2. Every row has one of the three labels.
3. The count of "stays human" rows is in the README's status line, because that number is the honest promise.

## 5. Not this task

Building anything. Fetching the client's site. Guessing a row he did not give.
