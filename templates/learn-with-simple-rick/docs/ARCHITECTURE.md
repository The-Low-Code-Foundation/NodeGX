# Architecture

## Page map

- **Thread** (`Pages/Thread`) — The learner's conversation: one message at a time, the reply bar at the bottom, the conversations drawer, the summary block and reset (LOOK.md 1–13).
- **Sign in** (`Pages/Sign in`) — Email, then the six-digit code.
- **Privacy** (`Pages/Privacy`) — What is stored, what goes to Anthropic and how it is aliased (R3), in Richard's words.
- **Inbox** (`Pages/Inbox`) — Coach: learners sorted by who is waiting on Rick.
- **Learner** (`Pages/Learner`) — Coach: notes, objectives, sessions, conversations, the share link.
- **Coach thread** (`Pages/Coach thread`) — Coach: the conversation as the learner sees it, coach notes in a surface that cannot be mistaken for the reply bar, Claude mode.

## Data model

### Learner

One person Rick coaches. The learner reads their own row except the coach-only fields.

Fields:
- user (the _User it signs in as)
- email
- name
- language
- prefs (theme, font, size)
- aliases (the find-and-replace table for anything sent to Anthropic; coach-only)
- inviteToken
- package
- meetCode (their recurring Google Meet code)
- notes (coach-only free text)

Relationships:
- has many Conversation
- has many CoachNote, Objective, Session (coach-only)

### Conversation

One thread: a lesson, a session review or a follow-up.

Fields:
- learner
- title
- kind (lesson | session-review | follow-up)
- state (open | done | archived)
- language
- dubbed
- linkedFrom
- summary
- dueBefore
- shareable
- run

Relationships:
- belongs to Learner
- has many Message
- may link from another Conversation

### Message

One bubble in a run of a conversation.

Fields:
- conversation
- run
- seq
- from (rick | learner)
- origin (cut | typed | drafted | dictated)
- kind (text | clip | choice | question | paste | learner)
- body
- clip {url, start, end}
- options
- revealsAfter

Relationships:
- belongs to Conversation

### Progress

How far the learner has revealed a run.

Fields:
- learner
- conversation
- run
- lastSeq
- lastOpened

### CoachNote

Rick's private note on a learner, a conversation or a message. Never shown to the learner.

Fields:
- learner
- conversation
- message
- text
- on

### Objective

A goal Rick holds for a learner. Coach-only.

Fields:
- learner
- text
- setOn
- doneOn

### Session

A coaching session: Rick's prediction, what happened, the comparison. Coach-only.

Fields:
- learner
- at
- recordingDriveId
- predicted
- happened
- comparison
- reviewConversation
- reminderOn

### PushSubscription

Where to send 'Rick replied'.

Fields:
- learner
- endpoint
- keys

## Backend contracts

A NodeGX backend on the Hetzner box at training.digitalbricks.io. Sign-in by a six-digit code by email (SRK-001). Learners read their own rows through path rules; the coach-only fields are hidden per field; every learner write goes through a cloud function; staff (role:staff) and the studio's staff key write everything. Nothing is ever deleted; a reset is a new run.

## Decisions

Considered during scoping and deliberately not done:

- **A lesson page with the clips laid out as steps** — Richard: "Blog post. I'm already bored […] I'm overwhelmed already" (first mockup).
- **Intake and programme generated by Claude (the DBT template)** — "one of my big mistakes with Digital Bricks Training was trying to offload intake and programme development to Claude"
- **Branches by platform or level** — "People don't like choices in general" — choices are inconsequential and personal only.
- **Magic-link sign-in** — A link from a phone's mail app opens the browser, not the installed PWA; a six-digit code (R5).
- **Learners write rows directly** — A learner could post a message marked from Rick; every learner write is a cloud function.
